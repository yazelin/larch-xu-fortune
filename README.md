# 一席問命｜仙泉．香布纏．續

七門算命小攤已可離線遊玩，也可由 Larch 的 miniGame 卡片嵌入。原生 HTML、CSS、JavaScript，沒有套件或外部字型、腳本、圖片依賴。紫微標示「下回」。本 repo 不含魏續的第一次問命劇情，那一段由作者在主專案另寫。

直接用瀏覽器開 `index.html`。也可執行 `python3 -m http.server 8000`，開 `http://localhost:8000/`。線上版：https://yazelin.github.io/larch-xu-fortune/ （GitHub Pages，main 分支根目錄，不必建置）。畫面使用《仙泉．香布纏．續》的遊戲畫，依 [LICENSE-CONTENT](LICENSE-CONTENT) 內容授權，不適用程式碼的 MIT 授權。

## 怎麼玩

| 算法 | 互動與內容 | 代號 |
|---|---|---|
| 測字 | 輸入一個漢字；358 字依現代正體字形拆部件。表外字請玩家依字典補選部首、填總筆畫，再給通用解語。 | `cezi` |
| 鳥卦 | 可報稱呼；小鳥走過一排卦箋、叼箋，玩家展開三十二箋之一。稱呼不影響隨機結果。 | `bird` |
| 塔羅 | 洗牌後依序抽、翻三張，左至右為過去、現在、未來；二十二張大阿爾克那，不重複抽取，正逆位各自判讀。 | `tarot` |
| 星座 | 選月日，查常見熱帶黃道的太陽星座日期表。 | `zodiac` |
| 相面 | 自選眉、眼、鼻、口、耳，再合讀解語。不開鏡頭。五官細項明示為未核實的擬寫。 | `face` |
| 日者擇日 | 選出行、嫁娶、動土、沐浴、葬、見官或學書，以裝置今日的干支讀日禁。只有核到的規則斷宜忌，其他情形明言未可定。 | `day` |
| 轉式盤 | 選所問之事、旋動天盤、讀八宮之一；天圓地方、二十八宿為造型參照。明示為意象遊戲。 | `wheel` |

深淺色隨裝置設定，右上「換燈色」可切換。按鈕可用觸控與鍵盤；減少動態效果的裝置會略過主要動畫。嵌入版隱藏作者頁尾。獨立遊玩時不留永久存檔，重新整理會清空計次；Larch 版由卡片讀寫專案變數。

## 網址參數

```text
?method=cezi&teller=市口問命翁&embed=1
```

`method` 使用上表代號，不帶時顯示七門選單；未知代號會回選單並提示。`teller` 為算命仙稱呼，以純文字呈現，最多四十字元。`embed=1` 隱藏頁尾並等候宿主回傳存檔；如果只是直接開網址，仍可遊玩。

不傳姓名、生日、五官或問題給宿主，只有各門計次與最近結果代號。表外測字的結果代號會包含漢字、部首和筆畫，這些屬於該次結果。

## 文稿與檔案

所有解語、牌名、卦箋與判詞放在 [content/算命.md](content/算命.md)，每門一節 JSON。修改後執行：

```sh
python3 tools/build_data.py
node --test
```

編譯產物 `data/fortunes.json` 已提交。HTTP／Pages 版直接讀 JSON；瀏覽器禁止 `file://` 讀 JSON，因此直接開檔時改讀同一腳本同步產生、內容完全相同的 `data/fortunes.js`。只在改文稿時重編，部署可直接使用已提交的產物。

`assets/core.js` 是可獨立測試的運算，`assets/app.js` 是畫面、互動 SVG 與訊息處理；`assets/art.js` 對應 `assets/img/` 的四十二張遊戲畫，不改結果代號。圖片皆延遲載入，塔羅與星座結果出現時才建立該圖。隨機採裝置亂數；測試可注入固定種子。

## 嵌進 Larch

完整欄位與十四個專案變數見 [larch/README.md](larch/README.md)。把 `larch/card.html` 全文貼進 miniGame 卡的 `miniGameHtml`，設定讀寫變數；遊戲與卡片是兩層 iframe。

| 方向 | 訊息 | 資料 |
|---|---|---|
| 遊戲 → 卡片 | `fortune:ready` | 要求還原存檔；未回應會重試。 |
| 卡片 → 遊戲 | `fortune:state` | `state: {version: 1, counts: {...}, last: {...}}`，無存檔也可傳 `null`。 |
| 遊戲 → 卡片 | `fortune:save` | 同格式；解語顯示後加一次，不等離席才存。 |
| 遊戲 → 卡片 | `fortune:exit` | `complete: true, result: {method: "bird", id: "bird-01"}`。未完成離席則 `complete: false, result: null`。 |

塔羅代號保留三個牌位與正逆，例如 `tarot-00-u_tarot-08-r_tarot-21-u`。相面代號保存五個選項；日者代號保存干支、事項與判詞規則。`method` 與 `id` 合起來就是「算法＋哪一張或哪一段」的穩定識別。

卡片把 `save` 轉成兩則 `larch:set {name, value}`，只寫該門的計次與最近代號。收到有效 `exit` 後等二百四十毫秒，送 `larch:complete {result: "exit", payload: {complete, result}}`。同一回的重複存檔及離席不重複計次；來源須是指定 iframe。卡片另核對遊戲網址來源；Larch 把卡片放在沙箱 iframe 裡，沙箱會傳到遊戲那一層，這時遊戲的來源是 `null`，卡片照樣只認自己開的那個 iframe，回給遊戲改用 `*`（2026-10-23 在 Larch 播放器實測：沒這樣處理時遊戲收不到存檔、離席也回不去）。遊戲接受直接嵌入的父視窗，以相容不透明來源的宿主沙箱。

## 驗收

`node --test` 跑運算、遊戲腳本與真實卡片程式的訊息模擬測試。測項包含二十四個星座交界日、測字表內與表外、五個已知干支日期、固定種子的鳥卦與塔羅、七門遊戲完成離席、存檔去重與來源拒絕。來源見 [tests/SOURCES.md](tests/SOURCES.md)。另驗證二十二張牌、十二星座、七門與攤位共四十二張圖片的對應、WebP 檔頭與尺寸資料，並以暫存目錄故意各少一張牌、星座、門別及攤位圖作負控制。可單跑 `node tools/check_art.cjs`。DOM 模擬測試不驗證瀏覽器排版。

瀏覽器驗收另執行：

```sh
node tools/browser_check.cjs
```

預設使用 `~/line-sticker-studio/node_modules/playwright` 與 `/usr/bin/google-chrome`；可用 `PW_MODULE`、`CHROME_PATH` 指定。程式在桌機淺色、手機深色各截一張完整選單，兩種尺寸各玩七門，並開 `tests/embed_host.html` 讓真實卡片與遊戲往返。截圖寫到 `/tmp/fortune/shots/`，結果寫到 `/tmp/fortune/browser-results.json`。不需測試伺服器，嵌入測試由 Playwright 路由提供同源靜態檔。

2026-10-23 換上遊戲畫後跑過一次：桌機、手機兩種尺寸七門都玩完，嵌入往返沒有錯誤；另外捲到頁尾確認選單八張圖都載入，塔羅逆位的牌圖轉了 180 度，星座結果圖也有載入。不可把 Node 模擬通過當成手機、桌機實測通過。另可在本機 HTTP 伺服器上手動開 `tests/embed_host.html?method=tarot`，上方會列出宿主收到的實際訊息。

## 考據與還沒核實

此處的「核對」是讀過下列電子文本，沒有完成版本校勘。遊戲解語是新寫的口吻，不是假冒古籍引文，也不以算命斷人壽夭。

- **測字**：採問字、拆形、借形解意的做法；拆字表是現代正體字形的視覺分解，不是字源分析。測字的早期文獻、每字拆法的逐條字典核對尚未完成。表外的部首與總筆畫由玩家提供，不假稱程式已有全字庫。
- **鳥卦**：採鳥取卦箋、開箋解讀的流程；卦箋全部原創。鳥卦起源、各地是否須稟告生辰、特定卦箋系統尚未核實，不自稱使用廟宇的三十二籤法。
- **塔羅**：牌序採偉特系，力量為第八、正義為第十一，愚者為零。牌意依現代常用象徵改寫，參照 [Waite《The Pictorial Key to the Tarot》](https://en.wikisource.org/wiki/The_Pictorial_Key_to_the_Tarot/Part_3) 所列正逆位與洗切程序；並非逐字翻譯偉特斷語。只用大牌與過去／現在／未來的三張陣是本作簡化；此牌陣的歷史來源與每張現代逆位說法尚未逐條核實。
- **星座**：使用常見日期表：牡羊三月二十一日至四月十九日，金牛四月二十日至五月二十日，雙子五月二十一日至六月二十一日，其餘見測試邊界。這是熱帶黃道的簡化生日表；太陽移宮每年時刻會變，沒有出生年、時間與時區，交界日無法精確排盤。性情解語為創作，不冒稱天文結論。日期表參照 [〈星星知我心？〉所列日期](https://www.mnd.gov.tw/File/8108)。
- **相面**：已讀 [《潛夫論．相列》](https://zh.wikisource.org/wiki/潛夫論/卷六) 的形貌、骨法、氣色、部位與德行總論；眉、眼、鼻、口、耳的具體選項沒有核到漢代定法，故全部明標「擬寫、未核實」。不拿近代相書說成東漢原文，亦不依外貌判壽命、疾病或善惡。
- **日者**：已讀 [《論衡．譏日》](https://zh.wikisource.org/wiki/論衡/70)；只有子日／卯日洗髮與丙日學書採其記載的日禁。《沐書》的「沐」是洗髮，沒有擴張成所有洗浴，更沒有推成出行宜忌。王充是在駁日禁。葬日還須月、地等條件，現有資料不能重建。《日書》的出行、嫁娶、動土、見官及其他日期的原簡文未核實，因此畫面回答「未可定宜忌」，不自編凶日表。裝置日期在當地午夜換日，不採命理派別的二十三時換日。
- **式盤**：已讀 [《史記．日者列傳》](https://zh.wikisource.org/wiki/史記/卷127) 的旋式記述。上圓下方、二十八宿是造型參照；八宮隨機停點不是六壬算法，解語明標為本作創作。天盤加時、月將、地盤、四課三傳的操作未核實，未實作。東漢市集與武威實物也未核實，不能當作考古重建。

後世、現代算法出現在故事中是作者允許的時代錯置。魏續的生辰與父母身世不在本攤補寫。
